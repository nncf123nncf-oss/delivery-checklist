# 納品前チェック

受託制作の「送信ボタンを押す直前の30秒」に開く、納品前チェックリストです。

添付漏れ・共有URLの権限ミス・古いファイルの送付は、納品したあとに気づきます。
気づく場所を、納品する前に動かすためのツールです。

## できること

- 案件名を書いておける（チェックはこの端末に1件だけ保存されます。案件ごとの保存には対応していません）
- 18項目のチェックリストを「ファイル / 公開設定 / 品質 / 連絡」の4カテゴリで確認する
- 完了数・完了率・残り件数をいつでも視界に置く
- 未完了項目をタップ（クリック）して該当箇所へ飛ぶ
- すべて完了したら「送信してだいじょうぶです」と確認する
- 次の案件へリセットする（2段階タップ。誤爆しない）

状態はブラウザの localStorage に保存されます。サーバーには何も送りません。

## 使い方

```bash
npm install
npm run dev
```

## ビルド

```bash
npm run build
```

`docs/` に出力されます（GitHub Pages のソースに `docs/` を指定する想定）。

## 設計上の決めごと

- **完了率は切り捨て**（`Math.floor`）。100% が出るのは全項目チェック済みのときだけ。
- **チェック済みの項目は消さない・並べ替えない。** 押した瞬間に下の行がせり上がると、次の指の着地点が変わって誤タップになる。
- **保存は項目 id をキーにしたオブジェクト。** 配列の添字で持つと、あとから項目を1つ足したときに全チェックが1つズレる。
- **保存キーに案件名を使わない。** 案件名を書き換えた瞬間にチェックが消えるため。
- **localStorage は必ず try/catch。** プライベートモードや容量超過で例外が飛んでも、初期状態に落として画面は動かす。
- **「初期状態に落とす」と「原本を消す」は分ける。** 読めなかった保存データは `deliverycheck.v1.broken.<時刻>` へ退避してから初期化する。知らない version も同じ扱い（踏み潰して保存しない）。
- **最初の描画では保存しない。** 読めなかった直後にそのまま書くと、目で読めば復旧できた原本が消える。
- **他のタブの変更を受け取る。** 2つのタブで開いたとき、後から操作したほうが先のチェックを消さないため。消えたことに気づけないまま「送信してだいじょうぶです」が出るのが一番まずい。
- **中身が同じときは書かない。** 他タブの変更を受け取って書き戻すと、保存が往復して止まらなくなる。

## 技術構成
